# Lumen Diary — визуальная спецификация v1

**FE‑02 · 21 ноября 2026 · На согласовании с Nivaro**

[Три эскиза на общей сетке](./fe-02-sketches.html) открываются в браузере как локальный файл. Переключатель сетки показывает 12 колонок. Режим «Сравнить без подписей» скрывает дату, заголовок и подпись под эскизом, сохраняя размеры блоков.

## Композиция

Открытка напоминает страницу фотоальбома. Кадр передаёт обстановку, линия под ним задаёт ритм, а дата и название помогают ориентироваться в дневнике. Плёночная фактура передаёт материал фотографии, свободное поле даёт паузу в тихих днях, ритм повторяющихся деталей поддерживает насыщенные записи.

Геометрия FE‑02.2 согласована. Координаты отсчитываются от верхнего левого угла холста 1080 × 1350. На экране пропорция открытки остаётся **4:5**. Внутренние зоны масштабируются вместе с холстом по одному коэффициенту — ширина открытки / 1080. Горизонтальные поля холста — 72 px. Рабочая ширина — 936 px, 12 колонок по 56 px с промежутками 24 px.

## Адаптивная раскладка листа сравнения

| Ширина окна | Колонки |
| --- | ---: |
| Меньше 898 CSS px | 1 |
| От 898 до 1336 CSS px, верхняя граница не включена | 2 |
| От 1336 CSS px | 3 |

Максимальная ширина каждой открытки — **420 CSS px**, зазор между карточками и рядами — **18 CSS px**. Ряды центрируются. В одноколоночной раскладке боковые поля листа не меньше 16 CSS px. В многоколоночной раскладке поля по 20 CSS px могут уменьшаться до 12,5 CSS px с каждой стороны, когда вертикальная полоса прокрутки шириной 15 CSS px забирает место. Ширина листа рассчитывается от фактически доступной ширины контейнера. Полный ряд из двух карточек по 420 CSS px с зазором занимает 858 CSS px, из трёх — 1296 CSS px.

В архиве миниатюра имеет пропорцию 4:5. Если preview_url равен null или фото не загрузилось, в том же месте отображается значок недоступного фото с текстовой альтернативой. Дата и полное название дня дублируются рядом с миниатюрой обычным читаемым текстом. Для даты кегль 14 CSS px и интерлиньяж 20 CSS px. Для полного названия кегль 16 CSS px и интерлиньяж 22 CSS px.

## Контраст текста

Минимальный контраст даты, заголовка и подписи — **4,5:1** на итоговом фоне под каждой текстовой зоной с учётом света и смешивания слоёв.

1. Проверить базовый цвет текста #F8EEE3 по минимальному контрасту в пределах всех трёх текстовых зон. Сохранить его, если в каждой зоне достигается 4,5:1.
2. Если текущий цвет не проходит, проверить чёрный и белый. Из подходящих выбрать цвет с лучшим минимальным контрастом по этим же зонам.
3. Если общего цвета нет, повторить выбор отдельно для даты, заголовка и подписи. Если ни один цвет не подходит в конкретной зоне, там появляется непрозрачная нейтральная подложка #F8EEE3 с чёрным текстом. Координаты и размеры зон сохраняются.

React-рендерер вычисляет самый светлый и самый тёмный фон зоны по ближайшей и дальней точкам прямоугольника относительно центра эллиптического градиента. Цвета смешиваются в sRGB, все каналы светлой точки не темнее основы. Для проверки нижняя и верхняя границы округляются наружу. Лист эскизов остаётся статическим и использует свои заранее проверенные цвета.

Целевой контраст линии относительно фона — 3:1. Рендерер сначала пробует цвет из палитры с 35% добавкой #F8EEE3, затем смесь результата с 55% белого или чёрного, затем чистый белый или чёрный. Под штрихом лежит контур того же пути толщиной 12 единиц холста. Если ни один цвет не выдерживает порог на всей полосе, белый штрих на чёрном контуре сохраняет различимую границу на светлых и тёмных участках.

## Как применять VisualModel

[Контракт в main](./api-contract.md) и [таблица правил](./mapping.md) задают значения. Ниже описано их применение на клиенте. Дата и фотографии берутся из записи дня, название открытки — из visual.caption. Жанр, темп и время суток на клиенте повторно не анализируются.

| Свойство | Поля | Что видит человек |
| --- | --- | --- |
| Свет | light.direction_deg, light.intensity, light.temperature_k | Мягкое световое пятно на фото и бумаге. 0° — сверху, 90° — слева, 180° — снизу, 270° — справа. Интенсивность меняет силу пятна, температура — оттенок от тёплого при 2700 K до холодного при 6500 K |
| Палитра и контраст | palette.colors, palette.saturation, contrast | Цвет бумаги и деталей берётся из палитры, насыщенность управляет их цветностью. Контраст меняет обработку фотографии и разделение светлого и тёмного. Читаемость текста контролируется отдельно |
| Плотность | density.value, density.elements | elements задаёт количество графических отметок внутри фоторамки. Чем выше value, тем ближе отметки друг к другу и тем меньше свободного поля. Дата, заголовок и линия сохраняют свои зоны |
| Фактура | texture.grain, texture.blur, texture.weather | grain задаёт заметность зерна. blur смягчает слой фотографии. rain добавляет наклонные штрихи, fog — полупрозрачную дымку, none оставляет базовое зерно. Эффекты ограничены фоторамкой |
| Линия дня | line.trajectory, line.amplitude, line.roughness, line.color_index | Траектория задаёт общий силуэт, амплитуда — размах, шероховатость — мелкие изломы, color_index выбирает цвет из palette.colors |

### Цвет и свет в React-рендерере

- Бумага смешивает 70% нейтрального #16171B с 30% первого цвета палитры в sRGB. Второй цвет окрашивает обводку фоторамки в смеси 50:50 с #A99B8A. Третий задаёт цвет декоративных отметок в смеси 65:35 с #F8EEE3. Линия берёт цвет по line.color_index. Если индекс отсутствует в палитре, используется первый цвет.
- При угле θ центр света в процентах равен x = 50 − 50 × sin(θ), y = 50 − 50 × cos(θ). Координаты округляются до 0,1%. Температура линейно смешивает #FFC078 при 2700 K и #BDDCFF при 6500 K. В центре бумажного градиента свет добавляется к каждому каналу бумаги по формуле `paper + (255 − paper) × tint / 255 × (0,10 + 0,45 × intensity)`. Центр и базовый цвет образуют непрозрачный градиент в sRGB с радиусами 85% ширины и 75% высоты холста.
- В фоторамке тот же свет работает в режиме screen с прозрачностью `0,13 + 0,42 × intensity` и затухает к 72% радиального градиента. Фильтры фото идут по порядку: яркость `0,73 + 0,46 × intensity`, контраст `0,75 + 0,55 × visual.contrast`, насыщенность `0,66 + 0,80 × palette.saturation`, затем размытие `1,2 × texture.blur` CSS px. Каждая плитка ограничивает размытие своими границами. Порядок фото соответствует photos[] из API. Если кадр не загрузился, его место занимает заглушка «Фото недоступно», соседи сохраняют позиции.
- Зерно состоит из двух фиксированных сеток точек с шагами 3 и 4 CSS px. Их общая непрозрачность равна `0,05 + 0,30 × texture.grain`. При rain поверх зерна идут наклонные штрихи, при fog добавляется полупрозрачное пятно, при none погодного слоя нет. Фактура не зависит от времени или генератора случайных чисел.

### Алгоритм линии дня

**Правило линии дня.** Одна траектория слева направо в зоне 936 × 180. Начало и конец отступают по 8 px от боковых краёв. Центральная ось — 90 px по вертикали зоны. Допустимые координаты центральной линии — 12–168 px по вертикали. Базовая толщина штриха — 7 px. rising поднимается, falling спускается, wave повторяет волну, flat держится вдоль оси. Изломы и амплитуда меняют форму пути внутри зоны. Обводка повторяет ту же геометрию и служит подложкой.

Берём 25 точек с равным шагом по x от 8 до 928 и параметром t от 0 до 1. Базовые профили по y: rising — `1 − 2t`, falling — `2t − 1`, flat — 0, wave — `sin(4πt)`. Профиль умножается на `12 + 48 × amplitude`. К нему добавляется дрожание `((2r − 1) × (4 + 8 × amplitude) × roughness × sin(πt))`, где r — очередное число из отдельного потока с начальным значением `seed XOR 0x9e3779b9`. Поток обновляет состояние как `(1664525 × state + 1013904223) mod 2³²` и делит его на 2³². Базовый размах и дрожание удерживают точки в пределах y=18…162.

Путь начинается в первой точке. Для каждой внутренней точки строится квадратичная кривая с контрольной точкой в ней и концом посередине до следующей. Последняя короткая секция доходит до правого края пути. Координаты округляются до 0,1 единицы холста. Одинаковая модель и seed дают тот же SVG-путь. color_index меняет цвет штриха, геометрия от него не зависит.

Расположение отметок и дрожание линии используют visual.seed как uint32 в JavaScript Number. Входные значения уже округлены. Для будущей FE‑05 motion.reveal_ms задаёт длительность проявки, motion.pulse_ms — период пульса. При prefers-reduced-motion сразу видна целая открытка. Для будущей FE‑06 карта показывает фактические source и text_ru из explain.

Условные сцены, даты, названия и формы пути подобраны вручную для проверки дизайна. Разные силуэты в фоторамках иллюстрируют разное содержание кадров и плотность композиции. Приложение и демо получают реальные записи из API. Backend-фикстуры остаются входами автотестов.

## Приёмка

1. Включить сетку. Сопоставить края даты, рамки, зоны SVG, заголовка и подписи у всех трёх открыток, в том числе при узкой ширине. Проверить, что линия укладывается в выделенную зону.
2. Скрыть подписи и сравнить характер открыток по силуэту линии, количеству деталей и фактуре. Повторить в оттенках серого, чтобы сравнить графику независимо от палитры.
3. Согласовать геометрию и трактовку полей с Nivaro. Контроль на трёх реальных днях проводится после появления входов TEAM‑03 и рендера FE‑04.
