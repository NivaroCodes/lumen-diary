# Деплой Lumen Diary

Приложение собирается в **один образ**: фронтенд (Vite) собирается в статику, а бэкенд (FastAPI) отдаёт её и API с одного адреса. Отдельный веб-сервер для фронтенда не нужен. **Секретов нет** — ни API-ключей, ни паролей.

## Переменные окружения (все необязательные, без секретов)

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT` | `8000` | Порт, который слушает сервер. На Render/Railway задаётся платформой автоматически. |
| `DATA_DIR` | `/data` (в образе) | Папка, где хранятся дни (SQLite + папки дней). |
| `MAX_UPLOAD_MB` | `10` | Максимальный размер одного фото. |
| `MAX_PHOTOS` | `5` | Максимум фото на день. |
| `CORS_ORIGIN` | `http://localhost:5173` | Нужен только при раздельном хостинге фронта и API. При одном образе не требуется. |

Вводить вручную при деплое ничего не обязательно: значения по умолчанию рабочие. Платформа сама подставит `PORT`.

## Вариант A. Docker (локально или любой хостинг с Docker)

```bash
docker build -t lumen-diary .
```

```bash
docker run -p 8000:8000 -v lumen-data:/data lumen-diary
```

Откройте `http://localhost:8000`. Том `lumen-data` сохраняет дни между перезапусками.

## Вариант B. Render (Blueprint)

В репозитории есть `render.yaml`. В Render: **New → Blueprint**, выберите репозиторий — сервис создастся из `Dockerfile`. Проверка здоровья: `/health`.

Бесплатный диск Render **не сохраняется** между деплоями. Чтобы дни не терялись, подключите платный диск на `/data` (раскомментируйте блок `disk:` в `render.yaml`).

## Вариант C. Railway

**New Project → Deploy from Repo**. Railway соберёт `Dockerfile` сам. В настройках сервиса при желании задайте `DATA_DIR=/data` и подключите том (**Volume**) на `/data` для постоянного хранения. `PORT` Railway задаёт сам.

## Вариант D. Без Docker (две команды)

```bash
cd frontend && npm ci && npm run build
```

```bash
cd backend && pip install -r requirements.txt && DATA_DIR=./data uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Бэкенд находит собранный фронтенд в `frontend/dist` относительно корня репозитория.

## Что нужно сделать вручную (и чего не делать)

- **Подключить репозиторий** к Render или Railway через их веб-интерфейс (вход через GitHub).
- **Подключить постоянный том** на `/data`, если дни должны переживать перезапуск (на бесплатных планах хранилище эфемерно).
- Секреты, токены и пароли вводить **не нужно** — приложение их не использует.

## Проверено

- Прод-сборка фронтенда (`npm run build`) проходит без ошибок.
- Бэкенд отдаёт с одного адреса: `/` (SPA), `/archive` (SPA fallback), `/assets/*.js`, `/api/days`, `/health` — все `200`.
- `docker build` в среде подготовки **не запускался** (нет демона Docker); Dockerfile повторяет проверенный путь запуска (uvicorn + `frontend/dist`). Соберите образ в своей среде перед деплоем.
